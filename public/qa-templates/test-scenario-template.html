測試情境｜行情流程與獨立案例

English查看空白範本查看填寫示例
Order Book 合成教學情境，非真實交易所實測。沿用本站 Fail Demo 的序號覆寫案例；價格、數量與時間是教學補充設定。Run、缺陷及證據名稱均為合成示例，沒有真實產品操作、證據附件或客戶核准。

這份文件回答什麼

同一行情流程拆成三個可獨立判定的條件：連續更新、舊事件、重連快照。Scenario 保存範圍與選取理由，執行結果另存 Run。

空白範本

〔必填〕每案都要有；〔條件式〕適用時必填，不適用寫原因。複製下方文字到案件文件後替換方括號內容。本頁為靜態範本，沒有編輯或儲存功能。

〔必填〕Scenario ID／版本：[ ]
〔必填〕標題與情境目標：[使用者在什麼條件下，要完成什麼事]
〔必填〕需求／判準版本：[REQ ID、來源與確認狀態]
〔必填〕風險 ID：[失效模式與影響]
〔必填〕角色、起始狀態、操作與結束狀態：[ ]
〔必填〕開始條件／依賴：[ ]
〔必填〕範圍／排除：[ ]
〔必填〕案例表：Case ID／版本｜目的｜資料分區／邊界｜Priority｜自動化適合度
〔必填〕每筆案例獨立判定；不同輸入條件不合併一個結果。
〔必填〕待確認問題／影響項目：[ ]
〔條件式〕Scenario 預設 Priority：[ ]；案例可覆寫並附依據
〔條件式〕資料與操作清理：[ ]
〔必填〕追溯：Case → 各次 Run → Defect；Scenario 不預填整體 Pass。

填寫示例

DEMO-SC-BOOK · v1.2｜維持 Order Book 的最新狀態

角色：合成行情消費端。起始狀態：SNAP-104。分別送入下一筆事件、舊事件，或重連後快照；各案獨立還原起始狀態。

需求：DEMO-REQ-NEXT／STALE／RECONNECT；風險 RISK-OB-SEQ；資料契約 DEMO-DC-MDQ v1.0。Scenario 預設 P1；案例可依風險覆寫，Severity 另於缺陷記錄。

案例／目的資料分區優先與自動化
TC-MDQ-016 v1.2：連續更新104 → 105；正常順序。P0，覆寫 P1，影響行情基本正確性；可自動化，本文未提供可執行腳本。
TC-MDQ-017 v1.2：拒絕舊事件104 收到 103；負向順序代表值。P0，覆寫 P1，防止狀態倒退；可自動化，本文未提供可執行腳本。
TC-MDQ-018 v1.2：重連恢復104 → 完整快照 106；狀態轉移。P1；可自動化，需明確的快照套用完成訊號。

資料與邊界

只用 103／104／105 說明舊值、基準與下一值；尚未測相同序號、跳號、亂序緩衝、零數量、缺值與斷線中事件。這三案不能宣稱完整覆蓋行情協定。

實案先解決 DEMO-Q-SEQ。若規則或可觀察條件不足，受影響案例先記 Blocked；規則改版則更新案例版本並新增 Run。

執行追溯

每案的步驟與預期見 Test Case；逐案合成結果見 Run Log；已知問題見 DEF-MDQ-004。
