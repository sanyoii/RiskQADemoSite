用 Order Book 合成失敗案例練習文件追溯。

English查看空白範本查看填寫示例
Order Book 合成教學情境，非真實交易所實測。沿用本站 Fail Demo 的序號覆寫案例；價格、數量與時間是教學補充設定。Run、缺陷及證據名稱均為合成示例，沒有真實產品操作、證據附件或客戶核准。

從需要的文件開始

以「舊序號 103 覆寫最新 104」為例，從規格一路追到 Run、缺陷與品質報告。先閱讀填寫示例，再複製相同頁面的空白範本到案件文件；九份文件與本入口都是靜態閱讀資料，中英文各十頁。

文件如何追溯

DEMO-SPEC-MDQ v1.2 / DEMO-DC-MDQ v1.0 DEMO-REQ-STALE ↔ RISK-OB-SEQ DEMO-SC-BOOK → TC-MDQ-017 v1.2 DEMO-RUN-FAIL-001 → DEF-MDQ-004 DEMO-QUALITY-MDQ：Blocked（合成）

追溯表 往下連到案例與缺陷；缺陷 也能回查失敗檢查點與 Run。

套用到自己的案件

  1. 複製 空白規格，填入實際來源與版本。
  2. 依目標產品重建資料、單位、時序、預期值、停止條件及證據。保留文件責任與追溯方法，不能只換產品名稱。
  3. 依 Case 範本 寫出可判定的檢查點；取得必要核准後才操作產品。
  4. 把當次結果記入新的 Run，保留歷史紀錄；由 品質報告 推導整輪狀態。

實案仍須確認的條件

行情協定、帳號／資料權限、完成訊號、時限、AI 使用、證據保存及結束條件，見 待確認問題。相同序號與跳號尚未定義；不要把教學假設當成交易所規則。

這組空白範本與方法源自公司範本；v1.3 已補齊 00～08 九份文件的中英文閱讀版，沿用本站 Order Book 情境。原始專案範本保持原樣；九份 Markdown 是正式撰寫庫。QA-Lite 維持 brief/design、run ledger、decision 三份紀錄；HTML 供閱讀與複製欄位，不新增狀態帳本。
