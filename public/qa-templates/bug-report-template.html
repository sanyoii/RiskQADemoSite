Bug Report

缺陷回報｜序號覆寫、影響與處置

English查看空白範本查看填寫示例
Order Book 合成教學情境，非真實交易所實測。沿用本站 Fail Demo 的序號覆寫案例；價格、數量與時間是教學補充設定。Run、缺陷及證據名稱均為合成示例，沒有真實產品操作、證據附件或客戶核准。

這份文件回答什麼

記錄觸發條件、預期與實際差異、影響及處置。缺陷分級與整輪結束條件判定分開。

空白範本

〔必填〕每案都要有；〔條件式〕適用時必填，不適用寫原因。複製下方文字到案件文件後替換方括號內容。本頁為靜態範本，沒有編輯或儲存功能。

〔必填〕Defect ID／標題：[觸發條件＋觀察到的影響]
〔必填〕版本／環境／時間／回報人：[ ]
〔必填〕QA 建議 Severity：[S1／S2／S3／S4]；影響依據：[ ]
〔必填〕委託方裁定：[待裁定／等級、依據、裁定人、日期]
〔條件式〕修復 Priority：[獨立填寫，待委託方決定]
〔必填〕追溯：需求／判準版本、風險、Scenario、Case／版本、Run、資料列、失敗 Step／CP
〔必填〕Preconditions／Test Data：[ ]
〔必填〕重現步驟：[編號；最少但完整]
〔必填〕Expected Result／來源：[ ]
〔必填〕Actual Result：[可觀察差異，不只寫 Fail]
〔必填〕影響／已知範圍／重現率：[成功重現次數／實際嘗試次數]
〔必填〕Evidence：[原始檔位置／時間／必要遮蔽，不能只給摘要]
〔必填〕成因：[product／test／environment／data／unknown；沒有證據不猜]
〔必填〕缺陷狀態／負責人／下一步：[ ]
〔條件式〕修正版本、重測 Run、回歸範圍與風險依據：[ ]
〔條件式〕延期接受：[有權人、理由、剩餘風險、責任人、重評日期]
整輪結果與結束條件判定另見品質報告；本缺陷只引用相關 Run 與證據。

填寫示例

DEF-MDQ-004｜舊序號 103 覆寫已更新至 104 的 Order Book

沿用本站 Fail Demo 的合成缺陷 ID；狀態 Triaged · demo，QA 建議 S1。無客戶裁定，根因 Unknown。

欄位內容
版本／環境／回報build-demo-1／DEMO-BOOK；DEMO-TESTER（虛構）。時間與證據見 DEMO-RUN-FAIL-001。
案例／資料／檢查點TC-MDQ-017 v1.2／STALE-103／attempt 1／S2～S3、CP2～CP3。
重現步驟載入 SNAP-104；只送 E-103 一次；在事件完成後讀回完整狀態。基準與數值依 DEMO-DC-MDQ v1.0。
預期／實際預期拒絕舊事件並維持 sequence=104、bid 100×2、ask 101×3；合成實際接受事件，sequence=103、bid 100×9、ask 101×3。
影響與重現行情狀態倒退，可能誤導下游判斷；未宣稱發生真實交易或損失。此處只展開一筆合成 attempt；本站另一處的合成重現敘述不作真實重現率。
責任／處置DEMO-ENGINEER 待調查；不得把猜測寫成根因。停止該案、保存快照，修正後新增 Run；未有修復或重測證據。

分級與狀態

欄位規則
SeverityS1：核心狀態正確性或完整性受損；此例建議 S1。S2：重要功能失效；S3：局部受影響且可繞行；S4：輕微問題。實案由約定的有權人裁定，另記依據。
Priority案例 P0 決定測試順序；缺陷修復 Priority 由責任人另定，不能用 P0 代替 Severity。
狀態New → Triaged → In Progress → Fixed → Verified → Closed；重測失敗回 Reopened。Fixed 只表示有修正宣稱，仍須新 Run 證據；本例停在 Triaged。

重測與回歸

修正後以 TC-MDQ-017 原輸入新增 Run，查 CP2 與 CP3。回歸選 TC-MDQ-016，確認正常更新未被一起拒絕；選 TC-MDQ-018，確認重連完整替換未受影響。相同序號、跳號及亂序先取得判準再擴充。不得把尚未執行的安排填成 Pass。
