00 QA Test Request

測試申請｜範圍、決策問題與授權

English查看空白範本查看填寫示例
Order Book 合成教學情境，非真實交易所實測。沿用本站 Fail Demo 的序號覆寫案例；價格、數量與時間是教學補充設定。Run、缺陷及證據名稱均為合成示例，沒有真實產品操作、證據附件或客戶核准。

這份文件回答什麼

00 Test Request 鎖定要測什麼、為何要測及誰能決定。資訊不足時維持 needs-information；需求尚未確認，不能直接排成可執行測試。

填寫示例：行情順序測試申請

欄位合成示例
Request／責任DEMO-REQUEST-MDQ v1.3；DEMO-REQUESTER／DEMO-QA（虛構角色）；提出日 2026-10-26，預計決定時間未定。
決策問題針對舊序號更新可能覆寫最新狀態，哪些行情測試需要執行、什麼條件才可進入 release review？目標是避免下游讀到倒退的 Order Book；沒有真實下單或損失主張。
Subject／變更教學 subject DEMO-BOOK／build-demo-1；真實目標 repo、branch、candidate SHA 與實際程式變更均 Unknown，不能拿本網站 SHA 冒充受測產品版本。
範圍／排除納入連續更新、舊事件拒絕、重連快照；排除真實 feed、下單、成交、資產及壓力。
已知資料／來源本站合成 TC-MDQ-016～018、DEF-MDQ-004 提供教材；實案的官方行情規格、Issue／PR、操作 Runbook、版本與有效測試證據均待提供。
風險／依賴RISK-OB-SEQ；依賴隔離 fixture、序號判準、完成訊號及快照存取。
限制／授權本示例只讀合成資料，不連外部服務；真實帳號、操作額度、AI 服務／可讀資料、證據存放／期限與清理均待核定。人力與實際交付時間未承諾。
公開／Intake教材可公開；禁止加入帳號、憑證、私有資料、內部連結。真實測試申請為 needs-information，風險層級 Unknown；尚無真人接受或審閱。

待確認與接續

DEMO-Q-SEQ 由產品／介接窗口確認行情協定、時序與完成訊號；影響三案及 DEMO-DC-MDQ。另確認真實 subject、資料授權、決定日期與責任人。回答需附來源版本及日期，再交 風險評估 與 Test Spec 重評；已有 Run 維持原判準版本。
