Bug Report

Defect report | Sequence overwrite, impact and disposition

繁體中文View blank templateView filled example
Synthetic Order Book teaching scenario, not a real exchange test. Based on this site's stale-sequence Fail Demo. Prices, quantities and times are supplemental teaching assumptions. Runs, defects and evidence names are synthetic; there was no real product execution, attached evidence or customer approval.

What this document answers

Record triggers, expected / actual differences, impact and disposition. Keep defect severity separate from the overall exit decision.

Retains the synthetic defect ID from this site's Fail Demo. Status Triaged · demo; QA-proposed S1. No customer decision; root cause Unknown.

Version / environment / reportbuild-demo-1 / DEMO-BOOK; DEMO-TESTER (fictional). For time and evidence, see DEMO-RUN-FAIL-001.
Case / data / checkpointTC-MDQ-017 v1.2 / STALE-103 / attempt 1 / S2～S3、CP2～CP3.
Reproduction stepsLoad SNAP-104; send E-103 once; read complete state after event completion. Baseline and values follow DEMO-DC-MDQ v1.0.
Expected / actualExpect rejection with sequence=104, bid 100×2, ask 101×3 unchanged. Synthetic actual: event accepted, sequence=103, bid 100×9, ask 101×3.
Impact and reproductionMarket-data state regresses and may mislead downstream decisions; no real trade or loss is claimed. This document expands one synthetic attempt only. Synthetic reproduction statements elsewhere on the site are not a real reproduction rate.

Severity and lifecycle

FieldRule
SeverityS1: core-state correctness or integrity compromised; S1 is proposed here. S2: important function fails. S3: limited impact with a workaround. S4: minor issue. In real work, the designated authority decides and records the rationale.
PriorityCase P0 determines test order. The owner assigns defect fix Priority separately; P0 cannot substitute for Severity.
StatusNew → Triaged → In Progress → Fixed → Verified → Closed; a failed retest returns to Reopened. Fixed is a fix claim requiring a new Run as evidence. This example remains Triaged.

Retest and regression

After a fix, append a Run using the original TC-MDQ-017 input and check CP2 / CP3. Regress TC-MDQ-016 to ensure normal updates are not rejected, and TC-MDQ-018 to protect full reconnect replacement. Confirm oracles before adding equal sequences, gaps or reordering. Do not mark unexecuted plans Pass.
