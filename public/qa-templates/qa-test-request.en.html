What this document answers

00 Test Request defines what to test, why, and who can decide. Keep needs-information when inputs are missing; unconfirmed requirements do not establish an executable test scope.

Filled example: market-data sequence test request

FieldSynthetic example
Request / accountabilityDEMO-REQUEST-MDQ v1.3; DEMO-REQUESTER / DEMO-QA (fictional roles); requested 2026-10-26, target decision time pending.
Decision questionWhich market-data tests address stale updates overwriting current state, and what is needed before release review? The objective is to prevent downstream readers from receiving a regressed Order Book. No real order or loss is claimed.
Subject / changeTeaching subject DEMO-BOOK / build-demo-1. The real target repo, branch, candidate SHA and code change are Unknown. This site's SHA must not stand in for the tested product version.
Scope / exclusionsInclude sequential updates, stale-event rejection and reconnect snapshots. Exclude real feeds, orders, executions, assets and load testing.
Available data / sourcesThis site's synthetic TC-MDQ-016 through 018 and DEF-MDQ-004 are teaching sources. Real official feed specifications, issue / PR, operating runbook, version and valid test evidence are still required.
Risk / dependenciesRISK-OB-SEQ; requires an isolated fixture, sequence oracle, completion signal and snapshot access.
Limits / authorityThis example reads synthetic data only and connects to no external service. Real accounts, operation budgets, AI services / readable data, evidence location / retention and cleanup require approval. Staffing and delivery time are not committed.
Disclosure / intakeThe teaching material may be public. Do not add accounts, credentials, private data or internal links. Real test intake remains needs-information, risk tier Unknown; no human acceptance or review has occurred.
