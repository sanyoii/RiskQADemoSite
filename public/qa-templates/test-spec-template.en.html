Environment label: DEMO-BOOK / build-demo-1; no real endpoint. Document status: teaching draft. Case IDs and the 104→103 failure come from app/run-records/fail-demo/page.tsx. The supplemental data contract is for teaching and has no product-owner approval.

DEMO-DC-MDQ · v1.0

Dataset DEMO-BOOK-DATA-v1 contains only the self-contained synthetic values below. Pair DEMO-BASE/QUOTE: price units QUOTE/BASE, quantity units BASE. These simplified rules do not represent any exchange's sequence ranges or WebSocket protocol.

ClauseDefinition
C1 Snapshots and eventsBaseline SNAP-104: sequence=104, bids=[[100,2]], asks=[[101,3]]. E-105: sequence=105, updates bid quantity at price 100 to 4. E-103: sequence=103, attempts to update the same bid quantity to 9. Reconnect SNAP-106: sequence=106, bids=[[100,5]], asks=[[101,6]]. Each case starts with its own SNAP-104 and must not contaminate later cases.
C2 Oracles and toleranceAfter a sequential update, expect sequence=105, bid 100×4, ask 101×3. After a stale event, expect sequence=104, bid 100×2, ask 101×3; the entire state must stay unchanged. After reconnect, expect the complete SNAP-106. Sequences are integers. Compare prices and quantities as exact decimals, with absolute tolerance 0 and no rounding. Zero-quantity deletion, missing values, equal sequences and gaps are undefined and need confirmation; missing is not zero.
C3 Timing and observationCompare before / after state at the event-completion checkpoint, or after full snapshot application for reconnect. This synchronous teaching scenario has no product-latency SLA and does not inherit the original 30-second wait. Record source as-of time, capture time and timezone separately. Sequence establishes order; wall-clock time does not replace it. Missing completion signals or observable state mean Blocked; elapsed seconds alone cannot establish Pass / Fail.
C4 Evidence and stoppingRetain event IDs, inputs, complete before / after state and checkpoints. Valid preconditions with a C2 violation mean Fail; inability to prepare isolated snapshots or observe state means Blocked. Preserve confirmed failures alongside other blockers. Stop the affected case after stale data overwrites state and retain snapshots; run other cases only on independent isolated data.

Execution, review and exit

Before execution

Check version, isolated fixture, event input, completion signal, oracle, data access, operation limits and evidence per case. Do not operate the product without required prerequisites; mark selected cases Blocked.

Review

Design review compares sources with cases. Result review inspects raw inputs / outputs before comparing conclusions. Switching roles within the same model is not independent review. These are synthetic filled examples with no human approval or product execution.

Three exit conditions

  1. Critical paths complete all required steps and checkpoints with valid evidence for the current version / environment.
  2. No unresolved S1. S2 is fixed with required retest / regression, or explicitly deferred by an authorized owner with reason, accountability and review date.
  3. No unexplained gaps in traceability.

Finishing testing, meeting exit criteria and authorizing release are separate. See the Quality Report.
